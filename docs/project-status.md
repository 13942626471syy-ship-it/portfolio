## 各项目值得看什么

### WhiteGZ：从资料到报告

资料与来源 → 事实和经营分析 → 结论支持检查 → 报告章节与图表。

- **已有材料**：报告与证据界面展示来源覆盖和待核验状态；图表界面使用合成数据。
- **阅读重点**：结论如何回到依据，报告与图表如何继续编辑。
- **仍需单独验证**：当前版本的检索、模型调用、导出和发布检查。截图中的财务数字不作为本页确认的投资信息。

### ISAD：从分析到建模产物

课程分析 → 行为与对象建模 → 结构化字段设计 → 图形生成与查看。

- **已有材料**：隔离 QA 的“作业提交与取消”示例，以及实际生成的主线顺序图。
- **阅读重点**：Electron 客户端、后端、MySQL 与 StarUML 的职责划分。
- **仍需单独验证**：异常分支、权限、工具失败后的恢复及当前安装包完整回归。画面中的“已生成”不等于语义验收通过。

### ERP Agent：从规则到可回放方案

规则与状态 → 候选方案 → 确定性执行器回放 → 诊断与比较。

- **已有材料**：学生助手的历史只读问答和规则连续追问界面。
- **阅读重点**：模型讲解、规则计算和经营动作的边界；主工程与助手副本的版本区别。
- **仍需单独验证**：主工程当前版本的完整经营链、搜索覆盖和独立复验。候选分数不代表官方成绩或全局最优。

### 拾光盒子 CampusLoop：从登记到运营

闲置登记 → 状态流转 → 组合包与预约 → 点位运营。

- **已有材料**：登记、组合包和运营台 3 张 MVP 界面。
- **阅读重点**：校园循环服务的业务组织与运营流程。
- **仍需单独验证**：正式认证、权限、支付退款、生产部署和数据恢复。预测、库存与经营指标均为演示用途。

### DNUI：校园积分业务的权限与一致性

积分申报 → 教师审核 → 业务记录管理。

- **已有材料**：项目范围、后端技术与维护重点的去标识化介绍。
- **阅读重点**：多用户业务流程、权限边界及记录一致性。
- **公开前置条件**：先准备独立演示环境和经审核的虚构数据。当前不提供校园业务截图、账号、数据库或服务器入口。

## 如何理解“有材料”和“已验证”

1. **界面或产物存在**：只能说明对应演示中可以看到什么。
2. **启动命令已整理**：便于授权协作者运行，不等于本轮实际启动成功。
3. **专项检查通过**：必须标明版本、命令和范围，不能替代完整验收。
4. **展示资料校验通过**：只覆盖链接、图片及发布文件，不证明产品业务正确性。

当前仓库没有公开产品的完整测试日志，也没有将历史结果标为最新通过。完整视频仍需画面、音轨和字幕审核。
